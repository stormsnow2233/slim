# 拾卷（Shijuan）· 原生安卓小说阅读器

多书源聚合搜索 + 原生阅读体验。Kotlin + Jetpack Compose，无 WebView，纯原生。

## 功能

- **多书源聚合搜索**：并发请求所有启用的书源，结果按书名合并去重，同一本书有几个源可用一眼看到
- **原生阅读器**：章内左右翻页（按屏精确分页）/ 上下滚动两种模式，5 种背景色，字号行距可调，进度自动保存
- **整本导出**：详情页三点菜单可直接导出 TXT / EPUB（EPUB 带 NCX + nav 双层目录），后台跑、完成通知
- **书架**：网格布局，显示阅读进度，长按可移除
- **书源管理**：18 个内置书源，可单独开关，支持一键体检看哪个能用
- **离线缓存**：读过的章节自动缓存，断网也能接着看
- **界面**：全屏沉浸书架、右上角快捷找书、全局边缘侧栏手势、过渡动画

## 2.18 书源修复

背着一堆「能搜到书、点进去没正文」的报障查了一遍，结论是三类完全不同的原因，分开修：

- **SF 轻小说「有目录没正文」**：源本身没坏，是目录开头十几章全是插图/人设页（`人设`、`书友画廊` 整卷都是图片），
  正文区只有一个 `<img>`，阅读器只排文字，点进去必然是空的。
  - `TocRule` 新增 `volume` / `skipVolume`：按卷标题整卷跳过（SF 跳过 `人设`、`书友画廊` 等）
  - `TocRule` 新增 `skip`：按章节名正则剔除（兜住没有卷结构的同类站点）
  - 「第一章正文过短」不再一律判死，`getChapter` 会明确报「这章是插图/图片章」
- **体检误报**：以前固定拿目录第一章试正文，正好撞上 SF 的插图章，好源被显示成 ✗。
  现在第一章不行会补测中间、四分之一处，报「目录 N 章 · 正文 M 字（换到第 k 章试的）」
- **速读谷搜不到书**：源站搜索会直接 302 到书页（单结果自动跳转），以前把落地的章节页当搜索结果，
  目录只有 6 条、正文是书籍简介。现在识别「被重定向到书页」并把书页本身当成唯一结果
- **假搜索结果**：`auto` 兜底会把站点的导航页/推荐位当成书籍列表（手机小说、bqg9 这类没有搜索入口的站）。
  现在兜底结果要求页面里真的出现搜索词，否则报「站点搜索不可用（返回的是导航/首页）」
- **起点换成 17K**：起点全站前端渲染 + 202 反爬，纯 HTTP 抓不到目录和正文（`m.qidian.com` 也只有 800 字节 JS 壳），
  这条源怎么改都是死的，删掉换成 17K（搜索 `search.17k.com/search.xhtml?c.q=`、目录 `/list/{id}.html`、正文 `.readArea div.p`）
- **目录真假判断**：章节名大量重复视为站点导航菜单而不是目录（手机小说 54 条「全部小说…」以前能混过去）
- **提示说准**：插图章 / 空页（同一章挂两条）/ 目录靠 JS 渲染 / 站点搜索不可用，四种情况各有各的文案，不再一律「正文内容过短」

- **默认书源**：默认开启改成 biqugese / sfacg / 17k / sudugu 四个实测能通的；书源开关的存储 key 升到
  `enabled_sources_v4`（书源表改过，老开关里可能还留着已下线的 `qidian`），读取时顺手过滤掉不存在的 id

实测（`.\gradlew.bat testDebugUnitTest`，本机网络）：biqugese、sudugu、17k、sfacg 四源搜索→目录→正文全通。

## 编译

需要 JDK 17 + Android SDK（compileSdk 35）。

```bash
# 修改 local.properties 里的 sdk.dir 指向你的 Android SDK
./gradlew assembleRelease
```

产物在 `app/build/outputs/apk/release/app-release.apk`。

签名配置在 `app/build.gradle.kts` 的 `signingConfigs` 中。正式发布请通过环境变量（`KEYSTORE_PATH`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`）或在 `local.properties` 中安全配置密钥库，切勿将私有证书与密码提交至公开仓库。

## 书源

书源定义在 `app/src/main/java/com/zaka/shijuan/data/Sources.kt`。

规则语法（简化版「阅读」规则）：

```
".bookbox a@href"       选择器@字段（text / html / texts / 任意属性名）
".a@text || .b@text"    左失败用右
".a@text##正则##替换"    文本后处理
```

加一个源：往 `Sources.ALL` 里加一条，字段照抄最像的那个。站点结构不固定的可以直接写 `auto = true` 走通用识别。
